# Серверная статистика и награды

Клиент отправляет действия над задачами и Pomodoro. Сервер проверяет владельца,
состояние объекта и условия награды. `GET /me/stats` читает статистику;
публичного `PATCH /me/stats` нет.

## Правила начисления

- Первое завершение задачи даёт 10 очков. `reward_claimed` сохраняется при
  возврате задачи в `pending`, поэтому повторное завершение награду не выдаёт.
- Завершение Pomodoro продолжительностью не менее 24 минут даёт 20 очков и
  увеличивает счётчик засчитанных Pomodoro. Продолжительность проверяется по
  времени БД. Порог соответствует существующему правилу для таймера на 25 минут.
- Если Pomodoro одновременно завершает задачу, начисляются также 10 очков за
  задачу, если её награда ещё не выдана. Базовая награда такой операции — 30 очков.
- Короткая сессия не даёт очков за Pomodoro и не увеличивает его счётчики.
  Явное завершение задачи при остановке таймера может дать обычные 10 очков
  за задачу; её можно завершить и без таймера.
- Ручное прерывание сессии с задачей сохраняет существующий штраф 30 очков.
  При сжигании задачи сбрасывается текущий стрик. Очки не становятся отрицательными.
- Прерывание свободной сессии и прерывание при удалении задачи не штрафуются.
- Массовое завершение использует правила одиночного завершения. Дубликаты ID,
  уже завершённые задачи и чужие задачи дополнительных наград не создают.
- За каждое достижение бонус выдаётся один раз. Бонусы не считаются новым днём
  активности. Общие очки могут превышать базовую награду действия за счёт достижений.

## Атомарность и повторные запросы

Бизнес-действия одного пользователя сериализуются блокировкой его записи в БД.
Проверка состояния, изменение задачи или сессии, выдача награды, пересчёт уровня
и выдача достижений выполняются в одной транзакции. Ошибка любой записи откатывает
всю операцию. Повторная остановка уже завершённой сессии без прежнего ключа
идемпотентности возвращает `404` и не изменяет статистику.

Команды задач (создание, PATCH, массовое завершение), Pomodoro и получения дневных
наград поддерживают `Idempotency-Key`. Успешный ответ хранится в той же транзакции.
Параллельные повторы возвращают одинаковый ответ без новых действий; ключ с другим
методом, URI или JSON дает `409 IDEMPOTENCY_KEY_REUSED`. Ошибки не сохраняются.
Ключи ограничены 128 символами, принадлежат аккаунту и пока хранятся бессрочно.
Логи и уведомления вызываются после подтверждения транзакции; при replay не повторяются.
Это не гарантирует доставку при падении процесса после commit: надежный outbox пока отсутствует.

Ответ команды содержит `operation_id`, реальные `result`/`rewards`, `stats`,
`unlocked_achievements`, `focus` и, для одного измененного ID, `task`.
Массовое завершение возвращает фактически измененные и пропущенные ID.

Уровень рассчитывается из очков. Стрик обновляется только при первом награждаемом
завершении задачи или засчитанном Pomodoro; календарный день определяется временем БД
в часовом поясе IANA из профиля (по умолчанию UTC).
Чтение профиля может выдать ранее доступное достижение, но не продлевает стрик.

## Ежедневные награды

`POST /me/quests/{code}/claim` выдает фиксированный серверный `reward_xp` выполненного
задания. `POST /me/rewards/daily-chest/claim` выдает 50 XP после выполнения всех заданий.
Получать отдельные награды заданий до сундука необязательно. Клиентские points
не используются. Уникальность обеспечена БД по аккаунту, локальному дню и коду.
Неготовое задание дает `QUEST_NOT_COMPLETED`, уже полученное — `REWARD_ALREADY_CLAIMED`
(409); повтор с тем же ключом возвращает сохраненный успех. Бонусы не продлевают стрик.

Журнал `daily_task_activity` фиксирует создание и переход в done, сохраняется после
удаления задачи и считает уникальные задачи с начала дня. Повторное сохранение done
и повторное открытие/завершение в тот же день не увеличивают счетчик. Миграция восстанавливает
доступную историю существующих задач по created_at и updated_at; более ранние переходы,
которых нет в БД, восстановить нельзя.

## Состояние фокуса

`GET /me/focus` возвращает 200 даже без сессии. `server_now`, `phase_ends_at` и
`remaining_work_seconds` позволяют корректно восстановить таймер после перезагрузки.
Дополнительный перерыв сохраняется на сервере, длится до пяти минут и продолжает
рабочие часы. `/me/focus/resume` досрочно завершает его в той же сессии.
После засчитанного Pomodoro начинается восстановительный отдых 5 минут, каждый четвертый —
15 минут. Цикл и отдых сохраняются в БД. Продолжение восстановительного отдыха запускает
следующую сессию; `/me/focus/rest/finish` завершает отдых без запуска. Досрочное
незасчитанное завершение не увеличивает цикл.

## Удаление

Удаление категории сохраняет задачи с `category_id = NULL`. Удаление задачи
завершает её активные сессии как `abandoned` и отвязывает все сессии от задачи.
История сохраняется. Эти правила реализованы миграцией `00018` и работают также
для массового удаления. Блокировки задач берутся до блокировок сессий, чтобы
завершение таймера и удаление задачи не блокировали друг друга циклически.

## Проверки

Модульные проверки: `go test -p 1 ./...` из каталога `backend`.

Проверки на отдельной PostgreSQL-базе требуют Docker:

```powershell
go test -p 1 -tags integration ./internal/storage/postgres -run 'Test(FrontendContracts|BusinessActions|DeletionRelationships)$' -v
```

Проверяются параллельные запросы, повторные награды, принадлежность объектов,
короткие сессии, отсутствие штрафа при удалении, сохранение истории и откат
при ошибке записи статистики. Для тестов создаются одноразовые контейнеры.
