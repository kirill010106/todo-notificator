# Проверки backend

Порог проекта — **80% покрытия операторов** рабочего Go-кода модуля `backend/`.
Это выбранный минимальный уровень для CI, а не универсальная гарантия качества.
Проверяются также ошибки, права доступа, атомарность и конкурирующие запросы.
Отдельные сервисы `activity-logger/` и `notifiers/` имеют собственные задания CI;
их код не входит в эту метрику.

## Что входит в покрытие

Модульные и интеграционные тесты запускаются совместно с `-coverpkg`: вызов
реального хранилища из теста HTTP-роутера также учитывается. В знаменатель входят
обработчики, middleware, хранилище, фоновые задачи, клиент журнала, конфигурация,
утилиты и точка входа `cmd`. Исключены только сгенерированные тестовые моки в
каталогах `mocks/`. Неиспользуемый обработчик изменения статистики не исключается
из метрики; отдельный тест гарантирует, что его маршрут недоступен.

Для проверки нужны Go 1.26+ и работающий Docker с Linux-контейнерами.
Интеграционные тесты создают отдельные PostgreSQL 16 и применяют миграции с нуля.
Базы разработки и production не используются. При явном `-tags integration`
недоступный Docker считается ошибкой, а не пропуском. CI также проверяет Docker
перед запуском.

## Запуск

PowerShell, из `backend/`:

```powershell
# Для Docker Desktop при необходимости указать Linux engine явно:
$env:DOCKER_HOST = 'npipe:////./pipe/dockerDesktopLinuxEngine'
docker info
if ($LASTEXITCODE -ne 0) { throw 'Docker is required for integration tests' }
$packages = (go list ./... | Where-Object { $_ -notmatch '/mocks($|/)' }) -join ','
go test -count=1 -p 1 -tags integration -covermode=atomic "-coverpkg=$packages" '-coverprofile=coverage.out' ./...
if ($LASTEXITCODE -ne 0) { throw 'Backend tests failed' }
go run -p 1 ../scripts/coveragecheck -profile coverage.out -min 80
if ($LASTEXITCODE -ne 0) { throw 'Backend coverage is below 80%' }
go tool cover '-html=coverage.out' '-o=coverage.html'
```

Linux/macOS, из `backend/` (так же запускается в CI):

```sh
set -eu
docker info > /dev/null
packages=$(go list ./... | grep -v '/mocks\($\|/\)' | paste -sd, -)
go test -count=1 -p 1 -race -tags integration -covermode=atomic -coverpkg="$packages" -coverprofile=coverage.out ./...
go test ../scripts/coveragecheck
go run ../scripts/coveragecheck -profile coverage.out -min 80
go tool cover -html=coverage.out -o coverage.html
```

`-race` требует поддерживаемую платформу и C-компилятор; в CI это Ubuntu.
На Windows можно добавить `-race`, если настроен совместимый C toolchain.
При нехватке памяти оставьте `-p 1` и задайте для процесса `GOMAXPROCS=2`.

Быстрые модульные тесты без Docker: `go test -p 1 ./...`. Их процент отдельно
может быть ниже 80%: порог применяется к полному набору с PostgreSQL.

## Отчёт и защита CI

`scripts/coveragecheck` объединяет одинаковые блоки, которые могут попадать в
профиль из нескольких тестовых бинарников при межпакетном покрытии. Счётчик
операторов учитывается один раз, а блок считается покрытым, если выполнен хотя
бы в одном наборе. Включение новых тестов не может искусственно увеличить
знаменатель. Профиль нормализуется на месте и совместим с `go tool cover`.
Повреждённый или пустой профиль вызывает ошибку. Сам инструмент имеет тесты
объединения, неверного ввода и точной границы порога.

CI останавливается при ошибках тестов, гонках данных или покрытии ниже 80%.
Профиль и HTML загружаются как артефакт `backend-coverage`.

## Основные сценарии

- Авторизация: неправильный ввод и пароль, ошибка сохранения токена, актуальные
  флаги аккаунта вместо устаревшего JWT, удалённый аккаунт, недоступная БД,
  параллельная ротация refresh-токена, отзыв токенов только нужного пользователя,
  срок действия при разных часовых поясах приложения и PostgreSQL.
- Задачи: валидация, права, категории, напоминания, лимиты, снятие значений через
  `null`, массовые действия и ошибки хранилища.
- Фокус и награды: один активный таймер, короткая сессия, штрафы, сохранение
  перерывов и цикла, повторные и параллельные начисления, replay по ключу,
  откат действия и награды, отсутствие побочных эффектов после отката.
- Ежедневный прогресс: пагинация Today, часовой пояс, запрет повторного получения,
  сохранение прогресса после удаления и отсутствие повторного счёта одной задачи.
- Оплата: состав запроса и ссылка возврата, недоступный провайдер, некорректный
  ответ, отмена, ошибка записи статуса или Premium и откат транзакции.
  Тесты не выполняют реальных платежей.
- Подтверждение email: криптографический токен, срок жизни, секрет webhook,
  успешная доставка и отказ сервиса; фоновая очистка продолжается после ошибок
  и завершается при отмене контекста.

Реальную доставку писем и оплату в тестовом окружении провайдера проверяют отдельно:
покрытие кода не подтверждает доступность внешних сервисов.

## Обнаруженная регрессия времени refresh-токенов

Поле `refresh_tokens.expires_at` исторически имеет тип `timestamp without time zone`.
Запись локального времени Go в такую колонку могла продлить срок действия токена
относительно времени БД. Новые записи и ротация сохраняют UTC; чтение и очистка
сравнивают срок с явно заданными часами UTC. Существующие значения трактуются как UTC,
что сохраняет поведение стандартного окружения с БД в UTC. Ошибочный исторический
часовой пояс отдельной старой записи автоматически восстановить невозможно.
