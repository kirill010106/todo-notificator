# Обработка ошибок: четвёртый этап

Дата: 25 октября 2026 года. Завершение [плана](API-ERROR-HANDLING-REPORT-2026-10-25.md) после [инфраструктурного этапа](API-ERROR-INFRASTRUCTURE-2026-10-25.md).

Глобальный `Errors` и поиск машинного кода по сообщению удалены. Обычный `router.New` использует полные ответы источников ошибок, без перехвата и повторной сериализации тела. Recorder внутри `Operation` сохранён: он участвует в транзакционном исполнении и сохранении успешных ответов.

## Согласованность и оставленные адаптеры

- В backend больше нет `Errors`, `defaultCode`, `normalizeErrors`, `NewWithoutErrorNormalizationForTest` и `ErrorCode`. Все подключённые источники ошибок прошли миграцию в предыдущих этапах; текущие проверки используют только рабочую сборку роутера.
- JSON-ошибки сравниваются целиком по значениям и типам. После удаления повторной сериализации допустимы порядок ключей DTO и завершающий перевод строки JSON Encoder; побайтовая идентичность ошибок не заявляется. Для успешных baseline-ответов сравниваются исходные байты.
- HTTP-статусы, Content-Type, Retry-After, предусмотренные поля, legacy null и исключения webhook сохраняются. Content-Length формируется HTTP-сервером по фактическому телу, а не принудительно удаляется внешним буфером.
- `SendError`, `RenderContractError`, account/contract/operation-адаптеры оставлены: они сохраняют числовой/строковый/отсутствующий status, поля и публичные сообщения, а записывает JSON общий рендерер.
- Эвристики frontend не удалялись автоматически. Текущие start/active используют общие `CONFLICT`/`NOT_FOUND`; legacy-тексты и варианты старого backend также поддерживаются. Удаление этих ветвей сейчас меняло бы сообщения пользователю. Серверный машинный код больше не выводится из текста.
- Не подключённые старые auth/register, auth/verify и stats/update не удалялись в рамках этой задачи. Они используют прежние DTO, но не являются источниками действующего HTTP API. Их отдельная зачистка не нужна для удаления глобального нормализатора.
- Глобальный буфер действительно устранён: сетевой тест подтверждает выдачу данных до завершения обработчика. Это проверка поведения, а не измерение выигрыша задержек или памяти.
- Изменения SQL, схемы БД, токенов, прав, идемпотентности и after-commit действий не требовались. Доставка журнала остаётся best-effort; реальных платежей, SMTP и деплоя не было.

## Проверки

Целевой backend-набор с `-p 1 -race -tags integration -count=1` прошёл: router, apiresponse, contracts. Проверены 65 baseline-сценариев, откат после промежуточного изменения в PostgreSQL, конфликт ключа команды, текущий request_id, логи/метрики, отсутствие глобального буфера по реальному HTTP и 52 формы JSON.

`python -m unittest discover -s scripts -p 'test_api_error_contract.py' -v`: три проверки согласованности OpenAPI прошли. Схема не менялась.

Полный backend-набор выполняется по [BACKEND-TESTING.md](BACKEND-TESTING.md): `-count=1 -p 1 -race -tags integration -covermode=atomic`, с coverpkg всех рабочих пакетов без generated mocks. Отдельные игнорируемые артефакты: `backend/coverage-error-finalization.out` и `.workbench/error-baseline-20261025/backend-finalization.log`.

Окончательные результаты:

- Полный backend-набор завершился с кодом 0: все пакеты, PostgreSQL, миграции, `-race`, откаты и конкурентные команды прошли. Нормализация `go run -p 1 ../scripts/coveragecheck -profile coverage-error-finalization.out -min 80` прошла: **84,23% — 4363/5180 операторов**, порог 80% достигнут.
- Из `frontend/`: `npm test` — **119 тестов в 12 файлах прошли**; `npm run build` — успешно, включая TypeScript. Сохранена проверка старых/current payload и повторных команд. Код frontend в этом этапе не менялся; Playwright повторно не запускался.
- Все восемь оставшихся изменённых Go-файлов этого этапа отформатированы. `git diff --check` прошёл; ссылки всех отчётов API-ERROR проверены, битых нет. Хеши двух исходных JSON-fixtures совпадают с началом этапа.
- Поиск по Go-исходникам подтверждает отсутствие удалённых функций и тестового переключателя; recorder команды остался единственным recorder в middleware/contracts.

Рефакторинг рабочего потока ошибок завершён с оговорёнными адаптерами совместимости. Производительность в миллисекундах/памяти не измерялась. Остальные Go-модули не менялись, их наборы не запускались. Результаты относятся к локальным проверкам, не удалённому CI. Коммитов и PR не создавалось.
