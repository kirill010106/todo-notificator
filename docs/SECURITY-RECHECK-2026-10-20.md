## Исключённое замечание №4

**Неатомарность публичной регистрации не воспроизводится в текущем маршруте.** [router.go:143](../backend/internal/http-server/router/router.go#L143) вызывает [account.Handler.Register](../backend/internal/http-server/handlers/account/account.go#L75). Его [RegisterAccount](../backend/internal/storage/postgres/account.go#L69) открывает одну транзакцию: пользователь → verification token → outbox → refresh token → commit. Ошибка любого промежуточного шага возвращается до commit, а отложенный rollback отменяет изменения.

Существующий `TestRegistrationRollsBackWhenDeliveryCannotBeQueued` выполнен успешно: внедрённая ошибка INSERT в outbox приводит к rollback. Это проверка транзакционного протокола через sqlmock; полноценная интеграция с PostgreSQL в данном аудите не запускалась.

Старый `handlers/auth/register.New` всё ещё существует и используется в старом E2E-наборе, однако рабочий router его не подключает. Переносить его дефект на публичную регистрацию неправильно. Дополнительно лимит активного регистрационного обработчика задан в [account.go:45](../backend/internal/http-server/handlers/account/account.go#L45).

- Отсутствие лимита и отсутствие backpressure подтверждены; авария по памяти, предельная пропускная способность и потеря production-данных не заявляются.
