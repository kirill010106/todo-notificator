# Новый веб-клиент и API 1.3

Один React + TypeScript + Vite клиент в `frontend/` заменяет прежние интерфейсы. Используются React Router, TanStack Query, CSS Modules и Radix Primitives. Manrope с кириллицей поставляется локально. Контракты описаны в [OpenAPI](openapi.yaml), правила начислений — в [BUSINESS-LOGIC.md](BUSINESS-LOGIC.md).

## Соответствие функций

| Функция                                          | Экран                                             |
| ------------------------------------------------ | ------------------------------------------------- |
| Лендинг, вход и регистрация                      | `/`, `/login`, `/register`                        |
| Поиск, фильтры, сортировка, массовые действия    | `/app/tasks`                                      |
| Создание и редактирование                        | Боковая панель, на телефоне полный экран          |
| План дня и просроченное                          | `/app/today`                                      |
| Категории и лимиты                               | `/app/categories`                                 |
| Pomodoro и свободные сессии                      | `/app/focus`, компактная панель, мобильный таймер |
| XP, уровни, серии, задания, достижения, журнал   | `/app/progress`                                   |
| Монеты, инвентарь и личные награды               | `/app/rewards`                                    |

## Серверные данные

Адрес задается `VITE_API_BASE_URL`, путь сохраняет `/api/v1`. Начальная загрузка использует `/me/bootstrap`; разделы загружаются по необходимости. Параллельные 401 используют одно обновление токена. Выход очищает серверный кеш. Premium и подтверждение email проверяются backend по текущему пользователю, а не устаревшим флагам JWT.

«Сегодня» использует `/me/today`, отдельные страницы `today` и `overdue` с полными счетчиками. Просрочены все сроки до серверного текущего времени, включая более ранние сроки сегодняшнего дня. В плане — сроки от текущего времени до начала завтра. Задачи без срока доступны в «Задачах». Часовой пояс берется из профиля (по умолчанию UTC), меняется в аккаунте. Списки и счетчики одного ответа читаются в одном снимке БД; между страницами изменения возможны.

Редактор отправляет `null`, чтобы снять срок, напоминание или категорию. Пропущенные поля не меняются. `/tasks` поддерживает границы `deadline_from`/`deadline_before` и `has_deadline`.

Команды задач, фокуса и получения дневных наград используют `Idempotency-Key`. Клиент сохраняет ключ в `sessionStorage` при сетевой ошибке, 5xx или 429 для повторной отправки. Сервер сохраняет успешный ответ атомарно с действием. Повтор с тем же ключом не повторяет награду; ключ с другим запросом получает 409. XP и достижения отображаются только из подтвержденного ответа; `PATCH /me/stats` отсутствует.

## Фокус

`/me/focus` всегда возвращает состояние, включая обычный `idle`. Время вычисляется относительно `server_now`, ограничено длительностью сессии и пересчитывается после возвращения во вкладку. Состояние обновляется каждые 15 секунд. После конфликта запуска клиент восстанавливает уже активную сессию.

- `focus`: рабочий таймер 25 минут. Раннее завершение привязанной сессии начинается с вопроса, выполнена ли задача. Следующий шаг объясняет доступный перерыв или последствия отказа. Свободную сессию можно остановить без штрафа.
- `extra_break`: один дополнительный перерыв до 5 минут. Рабочие часы продолжают идти согласно действующим правилам. «Продолжить работу» вызывает `/me/focus/resume` и возвращает к той же сессии. Начало/конец перерыва сохраняются на сервере.
- `recovery_break`: после засчитанной сессии 5 минут, после каждой четвертой — 15. Отдых и номер цикла сохраняются на сервере. Продолжение начинает новую сессию; отдельная кнопка завершает отдых без запуска.

Автоматическое завершение при нуле требует успешного ответа сервера. Ошибка сохраняет сессию и предлагает явный повтор, без бесконечного цикла запросов. После повторного сохраненного ответа актуальное состояние синхронизируется чтением `/me/focus`.

## Награды и локальный магазин

Награды ежедневных заданий получает `POST /me/quests/{code}/claim`, дневной сундук — `POST /me/rewards/daily-chest/claim`. Сервер проверяет готовность и уникальность по аккаунту, дню профиля и коду; размер XP не принимается от клиента. Статистика, достижения, состояние получения и результат сохраняются одной транзакцией. Дневной сундук дает 50 XP после выполнения всех заданий. Прогресс действий над задачами сохраняется после удаления; повторное сохранение выполненной задачи не создает новое завершение.

`RewardsRepository` оставляет монеты, оформление и личные награды локальными. Данные хранятся в `todo:rewards:v1:<userId>`. Маркер `todo:rewards:legacy-owner` связывает прежние общие `focus_coins` и `user_inventory` только с первым аккаунтом. Исходные ключи сохраняются; повторный вход не повторяет миграцию. Другие аккаунты получают новый кошелек с 50 монетами.

Индивидуальные подтвержденные действия дают локальные монеты с защитой от повтора по ID события. Массовые действия не начисляют монеты автоматически. Личные награды и покупки с реальным локальным эффектом сохранены. Бустеры без эффекта и золотой сундук отключены с объяснением: доверенного серверного кошелька пока нет. Локальный баланс нельзя обменивать на серверный XP.

## Что остается будущим контрактом

1. Серверный кошелек, каталог, инвентарь, личные награды, атомарные покупки и эффекты бустеров. Миграция локальных монет требует отдельной политики: браузерный баланс не является доверенным.
2. Стабильные курсоры Today для неизменного снимка между страницами.
3. Синхронизация темы, оформления и звука через профиль.
4. Пауза именно рабочих часов — отдельное изменение бизнес-правил. Текущий дополнительный перерыв часы не останавливает.

## Проверка и запуск

В `frontend/`: `npm ci`, затем `npm run dev`; адрес API скопировать из `.env.example`. Production: `npm run build`. Docker и Nginx обеспечивают прямое открытие маршрутов и проксирование `/api/v1`.

Vitest и Testing Library проверяют авторизацию, даты, команды, миграцию магазина, редактор и фокус. Playwright проверяет сетевые сценарии с фикстурами, 360/768/1440 px, обе темы, клавиатуру, прямые маршруты, Today, награды и восстановление таймера. Скриншоты находятся в `frontend/test-results/`. Backend-интеграционные тесты используют одноразовую PostgreSQL через Docker, включая гонки идемпотентности и откат.

Для выпуска обновить backend и frontend вместе. Backend при запуске применяет миграции `00019` и `00020` после существующей `00018`; перед обновлением сделать резервную копию. Новый клиент требует новых контрактов. До реального выпуска проверить доставку email, напоминаний и тестовую оплату YooKassa с настроенными сервисами. Офлайн-редактирование и синхронизация локального магазина между устройствами не реализованы.
