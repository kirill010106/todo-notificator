# ОГЛАВЛЕНИЕ

# ВВЕДЕНИЕ

Настоящее руководство пользователя предназначено для ознакомления с порядком развертывания, запуска и эксплуатации программного комплекса «ToDo Notificator».

Комплекс представляет собой монорепозиторную распределенную систему управления задачами и личной продуктивностью, включающую в себя бэкенд на языке Go, микросервис логирования активности, хранилища данных PostgreSQL и MongoDB, а также два независимых веб-клиента:
* современный SPA-клиент на стеке React 19, TypeScript, Vite и Ant Design;
* легковесный клиент на Alpine.js и Tailwind CSS со встроенным лендингом, расширенной статистикой и журналом аудита (директория `frontend`).

В документе подробно рассмотрены архитектура решения, инструкция по быстрому автономному запуску всего комплекса в Docker-контейнерах, а также функциональные возможности каждого из веб-интерфейсов со схемами экранных форм и пояснениями.

# 1 НАЗНАЧЕНИЕ И ТРЕБОВАНИЯ К СИСТЕМЕ

## 1.1 Назначение программы

Программный комплекс «ToDo Notificator» предназначен для автоматизации процессов личного и командного тайм-менеджмента. Система решает следующие задачи:
* централизованный учет задач с распределением по пользовательским категориям;
* приоритизация и контроль сроков исполнения (дедлайнов);
* применение техники Pomodoro (интервальной концентрации) с фиксацией рабочих сессий;
* сбор агрегированной статистики продуктивности, начисление игрового опыта (геймификация);
* аудит и логирование действий пользователя в нереляционной базе данных.

## 1.2 Системные требования

Для гарантированного функционирования всех компонентов комплекса рабочая станция пользователя или тестировщика должна удовлетворять минимальным системным требованиям, приведенным в таблице [#].

# 2 РАЗВЕРТЫВАНИЕ И ПОРЯДОК ЗАПУСКА ПРОЕКТА

## 2.1 Автономный запуск в среде Docker (Рекомендуемый способ)

Для упрощения тестирования и демонстрации в проекте предусмотрен автономный файл оркестрации `docker-compose.local.yml`. Он позволяет поднять все сервисы комплекса единой командой без необходимости ручной сборки бинарных файлов и установки компиляторов.

В состав автономного стенда входят следующие компоненты, представленные в таблице [#].

Таблица [#] – Состав сервисов локального тестового стенда

Имя сервиса | Назначение компонента | Внутренний порт | Внешний порт на хосте
:---|:---|:---:|:---:
`postgres` | Реляционная СУБД PostgreSQL 16 | 5432 | `localhost:5432`
`mongo` | Документоориентированная СУБД MongoDB 7 | 27017 | `localhost:27017`
`activity-logger` | Сервис аудита и логирования (Go, gRPC) | 50051 | `localhost:50051`
`backend` | Основной REST API сервер (Go) | 8082 | `localhost:8082`
`frontend-react` | Клиент на React 19, Vite и AntD под Nginx | 80 | `localhost:3000`
`frontend-alpine` | Клиент на Alpine.js и Tailwind CSS под Nginx | 80 | `localhost:3030`

Для запуска комплекса выполните в корневом каталоге репозитория команду, указанную в листинге [#].

```bash Листинг [#] – Команда запуска всего комплекса в Docker
docker compose -f docker-compose.local.yml up -d --build
```

После выполнения команды Docker Compose автоматически инициализирует тома хранения данных, проверит состояние готовности СУБД с помощью встроенных healthcheck-процедур, накатит миграции базы данных через механизм Goose и поднимет все веб-сервисы.

Процесс успешного развертывания контейнеров проиллюстрирован на рисунке [#].

![Терминал с успешным запуском контейнеров в Docker Compose](imgs/docker_compose_up.png)

Для проверки статуса контейнеров используется команда, приведенная в листинге [#].

```bash Листинг [#] – Проверка статуса запущенных сервисов
docker compose -f docker-compose.local.yml ps
```

Остановка стенда с сохранением данных в томах выполняется согласно листингу [#].

```bash Листинг [#] – Остановка тестового стенда
docker compose -f docker-compose.local.yml down
```

## 2.2 Локальный запуск клиентов без контейнеризации

При необходимости внесения правок в исходный код интерфейсов предусмотрена возможность прямого запуска фронтендов в среде разработчика.

### 2.2.1 Запуск React-клиента (`frontend-react`)

Для сборки и отладки React-приложения требуется установленная среда Node.js версии 20 и выше. Запуск выполняется последовательностью команд из листинга [#].

```bash Листинг [#] – Запуск React-клиента в режиме разработки
cd frontend-react/todo-notificator
npm install
npm run dev
```

По умолчанию dev-сервер Vite запускается по адресу `http://localhost:5173`. Запросы автоматически маршрутизируются на бэкенд по адресу `http://localhost:8082/api/v1`.

### 2.2.2 Запуск легковесного клиента (`frontend`)

Легковесный клиент представляет собой статическое приложение (HTML, Alpine.js, Tailwind CSS). Для его раздачи достаточно запустить любой HTTP-сервер статики, например `http-server`, согласно листингу [#].

```bash Листинг [#] – Раздача статического Alpine.js клиента
npx --yes http-server ./frontend -p 3030
```

Интерфейс становится доступен в браузере по адресу `http://localhost:3030`.

# 3 РУКОВОДСТВО ПОЛЬЗОВАТЕЛЯ: REACT-КЛИЕНТ

React-клиент спроектирован с упором на компактность, компонентную структуру и максимальную эргономику управления ежедневными задачами.

## 3.1 Авторизация и регистрация

При первом переходе по адресу `http://localhost:3000` пользователь попадает на экран авторизации. Форма содержит переключатель вкладок («Войти» и «Регистрация»), поля ввода электронной почты и пароля, а также индикатор надежности пароля.

Внешний вид экрана авторизации представлен на рисунке [#].

![Экран аутентификации React-клиента](imgs/react_auth.png)

Порядок регистрации нового пользователя:
1. Выбрать вкладку «Регистрация».
2. Ввести адрес электронной почты в поле «Email».
3. Ввести надежный пароль. Динамический индикатор отобразит стойкость пароля (наличие заглавных букв, цифр, длины от 8 символов).
4. Нажать кнопку «Зарегистрироваться». Система создаст учетную запись и автоматически переключит форму на вкладку входа.
5. Выполнить вход, указав зарегистрированные учетные данные.

При успешной авторизации полученные JWT-токены (`access_token` и `refresh_token`) сохраняются в локальном хранилище браузера (`localStorage`), после чего осуществляется автоматический переход на основной рабочий экран `/main`.

Для группировки задач используются категории. Пользователь может создавать произвольное количество тематических списков (например: «Работа», «Учеба», «Личное»).

Для добавления категории необходимо:
1. Ввести название категории в текстовое поле.
2. Выбрать цветовой маркер категории для визуальной дифференциации.
3. Нажать кнопку сохранения. Новая категория отобразится в списке фильтров.

## 3.4 Управление задачами

Создание новой задачи осуществляется через центральную форму. На рисунке [#] продемонстрирован процесс заполнения параметров задачи.

![Форма создания новой задачи](imgs/react_task_create.png)

Поля формы создания задачи:
* **Заголовок задачи** (обязательное поле) – краткая формулировка планируемого действия.
* **Описание** – расширенные заметки, ссылки или подпункты.
* **Категория** – привязка к одной из созданных категорий.
* **Срок исполнения (Дедлайн)** – дата и точное время завершения.
* **Оценка в Pomodoro** – планируемое число рабочих интервалов.

Список существующих задач отображается в виде карточек. Внешний вид карточки задачи представлен на рисунке [#].

![Карточка задачи и элементы управления](imgs/react_task_item.png)

Доступные действия с задачей:
* **Изменение статуса**: клик по чекбоксу переключает состояние задачи между `pending` (в работе) и `done` (выполнено). Выполненные задачи выделяются зачеркнутым текстом.
* **Редактирование**: изменение формулировки, срока или категории задачи.
* **Удаление**: безвозвратное удаление задачи с подтверждением действия во всплывающем диалоговом окне.

## 3.5 Использование таймера Pomodoro

В правой части экрана расположен виджет Pomodoro-таймера, предназначенный для работы по технике интервального фокуса. Внешний вид таймера показан на рисунке [#].

![Виджет Pomodoro-таймера](imgs/react_pomodoro.png)

Логика работы таймера:
1. Пользователь выбирает задачу из списка, к которой привязывается сессия.
2. По нажатию кнопки «Старт» запускается 25-минутный интервал концентрации.
3. Доступны кнопки «Пауза» и «Сброс».
4. По истечении рабочего интервала система начисляет очки продуктивности и переводит таймер в режим короткого (5 минут) или длинного (15 минут) отдыха.

## 4.2 Вход, регистрация и верификация Email

Форма входа позволяет авторизоваться по учетной записи, созданной в системе. Внешний вид формы представлен на рисунке [#].

![Форма входа и регистрации в клиенте Alpine.js](imgs/alpine_auth.png)

Особенностью статического клиента является поддержка подтверждения электронной почты:
* если email пользователя не верифицирован, в шапке рабочего стола отображается информационное предупреждение с кнопкой «Отправить письмо с подтверждением повторно»;
* при переходе по ссылке из письма с токеном вида `http://localhost:3030/?token=...` клиент автоматически передает токен на эндпоинт `/api/v1/verify`, активирует статус верификации и информирует пользователя всплывающим тостом.

Примечание: В связи с полным выводом почтовых нотификаций из активного контура проекта отправка писем верификации отключена; учетные записи активируются и работают непосредственно после регистрации.

## 4.3 Рабочая панель задач и расширенная фильтрация

Интерфейс личного кабинета после авторизации представлен на рисунке [#].

На рабочей панели доступны расширенные режимы фильтрации задач:

## 4.4 Раздел аудита и истории активности (Logs)

В статическом клиенте реализован просмотр детального журнала действий пользователя, хранящегося в MongoDB. Экран просмотра логов активности приведен на рисунке [#].

В журнале в хронологическом порядке фиксируются ключевые события:

Для удобства навигации по объемной истории реализована постраничная пагинация («Загрузить еще»).

Для повышения мотивации в клиенте используется система игрового прогресса. Экран игровой статистики отображен на рисунке [#].

Механика геймификации включает:

# 5 ДИАГНОСТИКА И МОНИТОРИНГ КОМПЛЕКСА

## 5.1 Исключение почтового сервиса (SMTP)

В итоговой конфигурации архитектуры программного комплекса поддержка внешних email-уведомлений и отправки почты по протоколу SMTP была полностью исключена.

Причиной такого архитектурного решения является нестабильность и жесткие ограничения бесплатных внешних SMTP-шлюзов (включая блокировки сторонних приложений со стороны почтовых провайдеров). Для обеспечения полной автономности, высокой скорости работы и надежности локального тестового стенда отдельный микросервис нотификаций (`email-notifier`) и промежуточный SMTP-перехватчик (`mailpit`) не включены в контур развертывания и не требуются для функционирования системы.

Регистрация пользователей, авторизация по протоколу JWT, управление задачами, таймер Pomodoro, аудит в MongoDB и геймификация работают в прямом автономном режиме без блокирующих внешних сетевых вызовов.

## 5.2 Мониторинг и диагностика сервисов

Для контроля за работой сервисов и локализации возможных ошибок используются стандартные команды чтения логов Docker Compose, приведенные в таблице [#].

Таблица [#] – Команды диагностики и мониторинга компонентов

Команда | Объект диагностики
:---|:---
`docker compose -f docker-compose.local.yml logs -f backend` | Логи REST API, применение миграций, HTTP-запросы
`docker compose -f docker-compose.local.yml logs -f frontend-react` | Логи веб-сервера Nginx React-клиента
`docker compose -f docker-compose.local.yml logs -f frontend-alpine` | Логи веб-сервера Nginx Alpine.js клиента
`docker compose -f docker-compose.local.yml logs -f activity-logger` | Обработка gRPC вызовов и запись документов в MongoDB
`docker compose -f docker-compose.local.yml logs -f postgres` | Состояние подключений и транзакций PostgreSQL
`docker compose -f docker-compose.local.yml logs -f mongo` | Операции чтения/записи MongoDB

# ЗАКЛЮЧЕНИЕ

Разработанный программный комплекс «ToDo Notificator» предоставляет пользователю полный спектр инструментов для эффективного управления задачами и временем.

Наличие двух независимых клиентских приложений позволяет гибко адаптировать систему под различные сценарии использования: компактный и реактивный интерфейс на React оптимален для повседневной работы со списком задач и таймером Pomodoro, в то время как многофункциональный клиент на Alpine.js предоставляет глубокую аналитику продуктивности и журнал аудита действий.

Подготовленный автономный Docker-контур обеспечивает развертывание всего комплекса в один клик, гарантируя независимость от внешних сетевых сервисов и легкость тестирования.
